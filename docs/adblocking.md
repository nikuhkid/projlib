# Brave ad blocking

The rewriting viewer runs Brave's actual `adblock-rust` 0.13.6 engine as WebAssembly in its service worker. It uses pinned snapshots of Brave's default ad, privacy and first-party filter bundles, including their resource replacements and scriptlet resources. Brave's original `content_cosmetic.ts` and `procedural_filters.ts` execute through a ProjLib renderer adapter. This is a browser-side integration and works with both Cloudflare and Wolfie routing. It does not start Brave or load a personal browser profile.

Scanner exposes Brave ad blocking controls while Proxy Mode is on. Standard is the initial mode. Aggressive also applies the default network lists to first-party requests and allows first-party cosmetic hiding. Off for this site bypasses blocking for that hostname. Settings persist in the viewer's browser storage and take effect by reloading the website. Counters report blocked network requests for the hostname during the current worker session, rather than counts of hidden elements.

HTTP decisions run before BareMux sends a request to either transport. Matching exceptions are retained. Blocking rules can return Brave's own replacement resource; URL-parameter removal updates the request URL. WebSockets are checked through the controlling service worker before opening the proxy socket. Site-specific scriptlets are injected before the page's scripts and passed through Scramjet's JavaScript rewriter. The native cosmetic bootstrap connects Brave's class/ID queries, procedural selectors, actions and first-party heuristics to the local engine and stylesheets.

The engine, filters and resources are verified against the pinned manifest before use. Immutable asset copies are cached by their SHA-256 digest. If the engine cannot initialize, the viewer reports failure; it does not describe an unfiltered connection as protected. No browsing URLs or credentials are sent to filter-list providers. Ordinary builds do not download changing lists. `scripts/update-brave-inputs.mjs` is an explicit updater that uses pinned Brave catalogue, mirror, resource, packager, browser-core and uBlock revisions; its manifest records all inputs and original notices.

The integration reproduces the blocking engine, lists, scriptlets and cosmetic executor within ProjLib's rewritten environment. Brave's native browser protections, privileged user-origin stylesheets, CNAME-resolution integration, browser Sync and fingerprinting protections are separate. Websites can behave differently in the rewritten environment. A successfully loaded YouTube homepage does not establish that every video ad or account state is handled.

The complete ProjLib bridge source, original cosmetic source, original filter texts, engine and dependency sources, resource archives, compiler record and licences accompany the source offer below the iframe. See `rewrite/NOTICE.txt` and `rewrite/adblock/vendor/manifest.json`.

To rebuild the engine, use the isolated GitHub Actions workflow or build `rewrite/adblock-engine/Cargo.toml` with Rust's `wasm32-unknown-unknown` target and its lockfile. The candidate workflow records the compiler, dependency metadata, vendored source and binary SHA-256. Download that artifact into a local directory and pass the directory to `node scripts/update-brave-inputs.mjs <artifact-directory>`. The updater requires `brave-adblock.wasm`, `dependencies-source.tar.gz`, `dependencies.json`, `cargo-config.toml` and `rust-toolchain.txt`. Review and commit the new snapshot; normal `npm run build:rewrite` rejects changed or mismatched source hashes.

Tests exercise real-engine exceptions, Standard/Aggressive first-party behavior, generic cosmetic exemptions, scriptlet generation and repeated Unicode ABI calls. Browser fixtures on both transport routes prove that blocked endpoints are not contacted, ordinary assets and exceptions load, scriptlets precede site code, generic and procedural cosmetics apply, blocked WebSockets stay local, ordinary WebSockets work, and per-site Off settings survive reload. Fixtures use controlled rules in addition to the real list snapshot; production assets have no test rules.
